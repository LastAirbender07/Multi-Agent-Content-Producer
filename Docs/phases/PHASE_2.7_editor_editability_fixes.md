# PHASE 2.7 — Editor Real Editability Fixes

## Status
APPROVED — Loop 1 complete (2026-09-06), ready to implement

## Problem Statement

Three categories of editing are broken today:

**A. Dual rendering confusion** — The slide preview (PNG thumbnail from Playwright) shows the old pipeline render. After the user edits in canvas and saves, the live Fabric canvas reflects their changes but the thumbnail still shows the old state until a backend re-render happens. Users see their "Edit in canvas" changes disappear on returning to the slide preview view. This erodes trust.

**B. Brand pill is locked** — `makeBrandPill` creates a Group with `selectable: false` on all children. The user cannot change the wordmark text (`@yourbrand`), the pill background colour, or the font. The right panel shows "CANVAS" (empty state) when the pill is clicked — no editable controls appear.

**C. Grouped component children are not individually editable** — When a user ungrouped a component (e.g. brand-bar, glass-card, bullet-list) in a previous phase, individual children become editable. But for components that are always presented as groups (pills, brand pills, outlined pills), children are permanently locked. The user cannot edit the text inside without ungrouping (which then loses the group semantics).

**After this phase:**
- Slide preview auto-updates to the latest canvas state immediately after save (no stale Playwright PNG shown)
- Brand pill text is editable via double-click (Fabric IText/Textbox editing mode within the group)
- Outlined pills (category pills) have their label text editable via double-click
- Right panel shows relevant controls (text content, color) when any pill is selected or its text child is active

## Root Cause Analysis

### A. Dual rendering

`SlidePngPreview.tsx` loads the PNG from `slide_NN.png` on disk — generated by Playwright during the pipeline run. After the user edits and saves via `canvasDropHandlers → api.saveCanvas()`, the backend re-renders the Fabric JSON to a new PNG (with a cache-bust `?v=` query). BUT the `versionQuery` is only passed to `SlidePngPreview` when the parent (`EditorPage`) propagates it via a state update. If the user exits canvas mode and returns to preview mode, the stale PNG may re-load.

**Real fix:** After `saveCanvas()` returns, the `versionQuery` returned should be stored in local state and passed immediately to `SlidePngPreview`. This is partially implemented but the state chain may have a gap.

Separately: for newly-created slides from the Templates panel, no Playwright PNG exists yet. The `SlidePngPreview` falls through to "No preview available" → shows "Open in canvas editor" button → user clicks it → canvas loads fresh. This path is CORRECT. The confusion only happens for slides that have an OLD Playwright PNG from the pipeline run.

**Simpler fix for now:** When the user is in canvas edit mode, on `saveCanvas()` success, immediately re-render the Fabric canvas to a data URL and cache it in a React ref. When the user exits canvas mode to preview mode, show this cached data URL instead of the stale PNG from disk. This eliminates the "shows old render" problem with zero backend changes.

### B. Brand pill children locked

`make-brand-pill.ts` line 73:
```typescript
const label = new fabric.Text(wordmark, {
  ...
  selectable: false,  // ← this prevents all interaction
  evented: false,
```

**Fix:** Set `selectable: true, evented: true` on the text child of brand pill. With `interactive: true` on the group (Fabric v7), the text child becomes directly editable via double-click. The right panel routing in `RightPanel.tsx` needs to handle `type=text` inside a group.

### C. Outlined pill text locked

Same issue in `make-outlined-pill.ts` line 73:
```typescript
const label = new fabric.Text(text.toUpperCase(), {
  selectable: false,
  evented: false,
```

## Implementation Steps

### Step 2.7.1 — Make brand-pill and outlined-pill text children interactive

**File:** `frontend/utils/canvasTemplates/shared/compact/make-brand-pill.ts`

Change the label `fabric.Text`:
```typescript
// Before:
const label = new fabric.Text(wordmark, {
  ...
  selectable: false,
  evented: false,
});
const group = new fabric.Group([bg, dot, label], {
  ...
  subTargetCheck: false,
});

// After:
const label = new fabric.Text(wordmark, {
  ...
  selectable: true,
  evented: true,
});
const group = new fabric.Group([bg, dot, label], {
  ...
  interactive: true,     // enables sub-target hit-testing
  subTargetCheck: true,  // needed alongside interactive
});
```

Same change in `make-outlined-pill.ts` for its label child.

**Note:** The Rect background `bg` stays `selectable: false, evented: false` — clicking the rect area selects the group, not the rect. Only the text child gets `selectable: true` so double-click on the label enters text edit mode.

**Test:** `npx tsc --noEmit` → 0 errors.

**File:** `frontend/components/editor/RightPanel.tsx`

```typescript

// To:
```

This ensures the TextPropertyPanel appears for both Textbox and Text objects.

**Also fix `FabricCanvas.tsx` onSelected handler** — the `SelectedObjectInfo.type` field derivation:
```typescript

  : obj.type === "image"
  ? "image"
  : "other";
```

## Known Constraints / Gotchas

- **`fabric.Text` vs `fabric.Textbox`**: `fabric.Text` is single-line, no wrapping. The brand-pill wordmark is intentionally single-line — correct type.
- **Group `interactive: true` changes hit-testing**: With `interactive: true`, a click anywhere on the pill routes to the nearest child. The Rect background (`selectable: false`) is still not selectable, so clicks on it route up to the group. Clicks on the text child route to the text child. This is the desired behaviour.
- **`subTargetCheck: true` requirement**: In Fabric v7, `interactive: true` on a group enables child rendering/events, but `subTargetCheck: true` is needed for the pointer-event routing to actually descend into children during hit-testing.
